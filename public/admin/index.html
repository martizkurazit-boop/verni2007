Вход.

Смотреть сайт

Пароль расшифровывает ключ доступа к репозиторию, сохранённый в этом браузере. На другом устройстве вход настраивается заново.

Первый вход в этом браузере. Нужен токен GitHub — им админка сохраняет статьи в репозиторий, и права по нему проверяет сам GitHub. Дальше он будет храниться здесь зашифрованным, а вы будете входить логином и паролем.

  1. Откройте github.com → Settings → Developer settings → Personal access tokens → Fine-grained tokens.
  2. Repository access — только репозиторий —.
  3. Permissions → Repository permissions → Contents: Read and write.

Смотреть сайт

Пароль никуда не отправляется и нигде не сохраняется — из него считается ключ, которым шифруется токен. Забудете пароль — просто настроите вход заново с новым токеном.

//Сборка

Авто-статья.

Вставьте текст целиком и загрузите фотографии — статья соберётся сама: короткие строки станут заголовками глав, длинные куски разобьются на абзацы, картинки разойдутся по тексту. Готовый черновик откроется в редакторе: проверяете, правите, публикуете.

Текст статьи

Первая строка — заголовок статьи, вторая (если это абзац) — лид. Короткая строка без точки в конце считается заголовком главы. Строки с «-» или «•» собираются в список. Если заголовков глав в тексте нет, они придумаются сами — потом поправите.

Частые вопросы

Первая строка — вопрос, следующие — ответ. Пары разделяются пустой строкой. Блок появляется под статьёй и размечается для поиска: такие ответы занимают больше места в выдаче и часто попадают в ответы нейросетей. Пусто — блока не будет.

Публикация

Категория

Снимите пометку, когда текст станет настоящим: она предупреждает читателя, что факты не проверены.

Связанные материалы

Отмечать необязательно. Под статьёй и в боковой колонке рекомендации появляются сами: сначала отмеченные здесь, затем материалы той же категории и с общими тегами, затем остальные свежие. Черновики и сама статья туда не попадают никогда.

# «Верните мой 2007» — сайт и админка

Онлайн-энциклопедия культуры, людей и явлений 1990-х и 2000-х. Публичная часть —
статический сайт (весь текст статей отдаётся в исходном HTML), админка —
отдельный защищённый раздел, который сохраняет статьи и картинки прямо в этот репозиторий.

```
.
├── content/              ← вся редакция: это и есть база данных
│   ├── site.json         ← название, описание, категории, счётчики, редиректы
│   ├── articles/*.json   ← по одному файлу на статью (черновики тоже здесь)
│   └── uploads/          ← обложки и картинки (WebP, три размера)
├── public/               ← то, что копируется в сборку как есть
│   ├── assets/site.css   ← стили публичной части
│   ├── assets/site.js    ← ~5 КБ: поиск, оглавление, видео, «показать ещё»
│   ├── admin/            ← админка (в сборке переезжает в каталог adminPath)
│   └── fonts/            ← Gilroy, 6 начертаний, WOFF2 с кириллицей
├── scripts/build.mjs     ← генератор статики, без зависимостей
└── dist/                 ← результат сборки (в git не хранится)
```

## Как это устроено

1. Статья лежит в репозитории как JSON.
2. Админка правит эти файлы через GitHub API — один коммит на сохранение.
3. Коммит в `main` запускает workflow `.github/workflows/deploy.yml`.
4. Workflow собирает статику и публикует её на GitHub Pages. Статья появляется на сайте примерно через минуту.

Никакой базы данных и сервера содержать не нужно: история правок — это история git,
резервная копия — это клон репозитория.

## Первый запуск (один раз)

1. **Запушить код в `main`.** Workflow срабатывает на пуш в `main`.
2. **Включить Pages:** Settings → Pages → Source: **GitHub Actions**.
   (Workflow пытается включить это сам, но прав может не хватить.)
3. Дождаться зелёной галочки в Actions. Сайт откроется по адресу
   `https://martizkurazit-boop.github.io/verni2007/`.
4. **Домен.** Сайт работает на `vernitemoy2007.ru`. DNS у регистратора (Timeweb):
   - четыре `A` для `@` → `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
   - `CNAME` для `www` → `martizkurazit-boop.github.io`
   - записи `MX` и `TXT` (SPF) остаются как были — почта на домене не затрагивается

   В репозитории: Settings → Pages → Custom domain → `vernitemoy2007.ru`, затем **Enforce HTTPS**
   (галочка становится доступной, когда выпустится сертификат — обычно минуты, иногда до суток).
   Адреса в canonical, sitemap, Open Graph и `robots.txt` пересобираются под домен сами:
   сборка берёт адрес из настроек Pages. Файл `CNAME` кладётся в сборку автоматически.

## Как опубликовать статью

1. Откройте `<адрес сайта>/2007/` — адрес задаётся в `content/site.json` → `adminPath`.
   Ссылки на админку в меню и футере сайта нет намеренно.
2. **Первый вход в этом браузере** — форма попросит логин, пароль и токен GitHub.
   Токен получают так: `github.com → Settings → Developer settings → Personal access tokens →
   Fine-grained tokens → Generate new token`, Repository access — только этот репозиторий,
   Permissions → Repository permissions → **Contents: Read and write**.
   Логин и пароль вы придумываете сами.

   Внимание на поле **Repository access**: нужно «Only select repositories» и этот
   репозиторий. Вариант «Public repositories (read-only)» даёт только чтение — вход
   пройдёт, статьи будут видны, а сохранение упадёт с ошибкой 403.
3. **Дальше вход только логином и паролем.** Из пароля выводится ключ (PBKDF2, 210 000 итераций),
   которым шифруется токен (AES-GCM); в браузере лежит только зашифрованный сейф. Ни пароль,
   ни токен в открытом виде не хранятся нигде и в репозиторий не попадают. После перезагрузки
   страницы пароль спрашивается заново: расшифрованный токен живёт только в памяти вкладки.

   Забыли пароль или меняете токен — ссылка «Забыли пароль или меняете токен» на экране входа
   стирает сейф и возвращает к первой настройке. На новом устройстве вход настраивается заново.

   **Чего это не делает:** пароль не защищает репозиторий — настоящий замок на записи это токен,
   права по которому проверяет сам GitHub. На статическом хостинге проверить пару логин-пароль
   негде: сервера нет. Пароль защищает токен на конкретном устройстве, и только.
3. «+ Новая статья» → заголовок (адрес подставится сам) → анонс и лид.
4. Текст собирается **разделами**. «+ Новый раздел» сразу добавляет три поля:
   заголовок H2, абзац и место под фото — то, из чего обычно и состоит кусок статьи.
   Внутри раздела пунктирные кнопки добавляют ещё абзац, фото, цитату, список или
   подзаголовок; стрелки в шапке раздела двигают его целиком, «Убрать раздел» удаляет
   вместе с содержимым. Раздел — это просто заголовок H2 и всё, что идёт до следующего:
   отдельной сущности в файле нет, поэтому уже написанные статьи открываются
   разделами сами, без переделки. Либо нажмите
   **«Вставить готовый текст»**, вставьте статью целиком, нажмите «Разобрать на блоки»
   и «Расставить роли автоматом» — дальше поправьте роли руками и нажмите «Собрать статью →».
5. Обложка: перетащите картинку в рамку справа. Она сама обрежется в 16:9 без искажения
   пропорций и сохранится в трёх размерах (1600/1000/600, WebP). Точку фокуса выберите
   в сетке 3×3 — по ней делается кадрирование. Alt-текст обязателен.
6. Ссылка на YouTube — необязательна. Пусто — блока видео на странице не будет.
7. «Предпросмотр» открывает статью в оформлении сайта, ничего не публикуя.
8. «Сохранить черновик» — материал остаётся в репозитории, но на сайт не попадает
   (в сборку черновики не выгружаются вообще, ни по какому адресу).
9. «Опубликовать» — через минуту статья в ленте, в sitemap и в RSS.

Смена адреса у опубликованной статьи автоматически добавляет запись в `site.json → redirects`,
и старый адрес начинает вести на новый.

## Проверка перед публикацией

В редакторе есть блок «Готовность к публикации». Красные пункты — то, что заметно
ударит по позициям или по читателю (нет подзаголовков, пустой alt у картинок,
короткий текст, нет SEO-описания), серые — желательное. Список считается на лету
по мере заполнения полей.

## Типографика

Сборка сама приводит текст в порядок: машинописные кавычки становятся «ёлочками»,
дефис между словами — тире, троеточие — многоточием, диапазон лет — коротким тире,
а после коротких слов и перед тире ставятся неразрывные пробелы, чтобы предлог не
оставался в конце строки. Внутри адресов ссылок типографика не применяется — там
она сломала бы адрес.

## Что ещё умеет сайт

- **Ленты и хабы:** главная, «Все статьи», категории, теги, `/with-video/` (только с
  выпусками), хабы по эпохам `/90s/` и `/2000s/` (собираются по тегам десятилетия),
  `/video/` со списком выпусков канала, `/about/`, `/saved/` («читать позже»).
- **Переходы на канал:** кнопка в шапке, липкая плашка в статьях с видео, карточка
  выпуска в конце статьи, блок новых выпусков на главной. Все ссылки с utm-метками
  и своим `utm_campaign` — в отчётах YouTube видно, что именно сработало.
- **Чтение:** полоса прогресса, подсветка активного пункта оглавления, кнопка «наверх»,
  кнопки «поделиться» (Telegram, ВКонтакте, копирование) и «читать позже».
  Отложенное хранится в браузере читателя и никуда не отправляется.
- **Автоперелинковка:** первое упоминание чужого героя в тексте становится ссылкой.
  Ограничения: регистр важен, начало предложения пропускается, не больше четырёх
  ссылок на статью. Короткие имена задаются полем «Имена для автоссылок».
- **Частые вопросы:** блок с разметкой FAQPage, заполняется в админке.

## Как читатель ходит по кругу

Под каждой опубликованной статьёй и рядом с ней рекомендации выстраиваются автоматически,
руками ничего заполнять не нужно:

- **Боковая колонка «Ещё по теме»** (на экранах от 1180px) — липкая, со своей прокруткой,
  до пяти материалов и ссылка «Все статьи».
- **Ссылка «Читайте также»** прямо в тексте — после абзаца, идущего за вторым подзаголовком.
- **Блок «Советуем почитать»** под статьёй — до шести карточек с обложкой, категорией,
  временем чтения и анонсом. Пока материалов хватает, он берёт не то же самое, что боковая
  колонка, а следующие по очереди — так на одной странице получается до одиннадцати разных
  внутренних ссылок.
- **Карточка «Следующая статья»** — ближайший по времени материал той же категории.
- Плюс хлебные крошки, кликабельная категория, теги и «Вернуться в ленту».

Очередь рекомендаций: отмеченные в админке → та же категория → общие теги → остальные свежие.
Текущая статья и черновики не попадают в неё никогда. Для SEO это и есть перелинковка:
каждая страница ссылается на соседние, а на телефоне работают все блоки, кроме боковой
колонки, — её заменяют ссылка в тексте и блок под статьёй.

## Категории

Раздел «Категории» внизу списка статей включает и выключает разделы и хранит их описания.
Выключенная категория и категория без опубликованных материалов не видны посетителям
нигде: ни в меню, ни в футере, ни в карте сайта.

## Картинки внутри статьи

Обложка — часть единой системы, поэтому кадрируется строго в 16:9 по точке фокуса.
Картинки **внутри текста** живут по другим правилам: они не кадрируются вообще,
сохраняется форма оригинала, файл только уменьшается до 1600 px по длинной стороне
и переводится в WebP.

Вёрстка подстраивается под форму кадра:

- **горизонтальный** — во всю ширину колонки, а на экранах от 1000 px чуть шире её,
  чтобы читался как иллюстрация, а не как вставка;
- **вертикальный** — по центру, не шире 520 px: иначе один снимок занимает три экрана;
- **квадратный** — по центру, не шире 600 px.

Размеры записываются в статью и попадают в HTML — благодаря этому место под картинку
резервируется заранее и страница не прыгает во время загрузки. Для поисковиков это
отдельный измеряемый показатель.

## Правила обложек

- строго 16:9, минимум 1600×900;
- без надписей поверх кадра — заголовок живёт под обложкой;
- одинаковая обработка: контрастно, холодновато, без глянца и виньеток, без ч/б;
- без рамок, скруглений и теней — рамку рисует вёрстка;
- лицо не в самом краю кадра: точка фокуса помогает, но не спасает совсем крайние композиции.

## SEO

Готово в сборке: статический HTML со всем текстом, уникальные `title`/`description`,
один `H1`, `canonical`, Open Graph и Twitter-карточки, `sitemap.xml`, `robots.txt`,
микроразметка `Article` и `BreadcrumbList`, страницы категорий и тегов, RSS, `llms.txt`
(карта сайта для ИИ-ассистентов), страница 404, редиректы при смене адреса.

Картинка для соцсетей: если у статьи нет обложки, подставляется фирменная
`/assets/og-default.png`. Логотип издания `/assets/logo-512.png` уходит в разметку
`Article` — Google просит его для карточки материала. Обе картинки лежат в `public/assets`
и перерисовываются вручную, если поменяется фирменный стиль.

Ссылки на площадки проекта (YouTube, Телеграм) добавляются в `content/site.json` → `social`:
они выводятся в микроразметке `Organization` как `sameAs` и связывают сайт с каналом.

`VideoObject` выводится только если в JSON статьи заполнен блок `video`
(`name`, `uploadDate`, `duration`, `thumbnailUrl`) — выдумывать эти данные нельзя,
за неверную разметку поисковики наказывают.

Из индекса исключены: админка (тегом `noindex`), поиск, черновики (их просто нет в сборке).

## Доступ для нейросетей

Осознанное решение владельца: материалы открыты для поиска, цитирования и обучения
моделей — трафик из ChatGPT и подобных сервисов и есть цель проекта.

- `robots.txt` разрешает всё всем, а ботов ИИ-сервисов называет **поимённо**
  (`OAI-SearchBot`, `ChatGPT-User`, `GPTBot`, `ClaudeBot`, `Google-Extended`,
  `PerplexityBot`, `CCBot` и другие): часть краулеров ищет в файле собственное имя,
  и отдельная запись снимает разночтения. Список задан в `scripts/build.mjs`
  константой `AI_AGENTS` — новых ботов дописывать туда.
- На всех индексируемых страницах стоит
  `max-snippet:-1, max-image-preview:large, max-video-preview:-1` — разрешение
  показывать сниппет любой длины и крупную картинку. Для ответов ИИ это важнее,
  чем для обычной выдачи: без него сниппет режется.
- `/llms.txt` — карта сайта для ассистентов, `/llms-full.txt` — полные тексты всех
  материалов одним файлом, чтобы модель не обходила сайт постранично.

Ничего дополнительно блокировать не нужно: на GitHub Pages нет ни файрвола, ни
антибот-защиты. Если сайт когда-нибудь переедет за Cloudflare — там в разделе
Security есть отдельный переключатель «Block AI Scrapers and Crawlers», и его нужно
будет **выключить**, иначе он отрежет ровно этих ботов независимо от `robots.txt`.

Пока сайт стоит на временном адресе `*.github.io`, **все страницы отдаются с `noindex`,
а `robots.txt` закрыт целиком** — чтобы потом не конкурировать с самим собой по одному
и тому же тексту. Как только `SITE_URL` станет собственным доменом, индексация
включается сама. Принудительно открыть временный адрес: переменная `FORCE_INDEX=1`.

## Быстрая индексация (IndexNow)

После каждой выкладки workflow сообщает Яндексу и Bing об изменившихся страницах —
они забирают их за минуты вместо ожидания планового обхода. Google протокол не
поддерживает и приходит по карте сайта.

Список адресов собирается из изменившихся файлов последнего коммита: опубликовали
статью — уйдёт её адрес и главная, а не весь сайт целиком. Ключ лежит в
`content/site.json` → `indexNowKey`, и он же должен отдаваться файлом в корне сайта:
`public/<ключ>.txt`. **Удалять этот файл нельзя** — без него поисковики отвергают
уведомления. Если ключ меняется, файл переименовывается вместе с ним.

Ошибка уведомления никогда не роняет выкладку: сайт к этому моменту уже опубликован,
а страницы в худшем случае попадут в индекс обычным обходом.

## Аналитика

Впишите номер счётчика в `content/site.json`:

```json
"analytics": { "yandexMetrika": "12345678", "ga4": "G-XXXXXXX", "webvisor": false }
```

`webvisor: true` включает запись действий посетителей — полезно на старте, чтобы увидеть,
где люди бросают чтение, но нагружает страницу, поэтому по умолчанию выключен.

Подтверждение прав в Яндекс.Вебмастере и Google Search Console — тремя способами:

- **мета-тег** — код в `content/site.json`:
  `"verification": { "yandex": "…", "google": "…" }`;
- **HTML-файл** — положить его в `public/`, оттуда он попадает в корень сайта
  (сейчас так подтверждён Яндекс: `public/yandex_0ed7e66fc11a2dc5.html`);
- **TXT-запись в DNS** — у регистратора, кодом сайт не затрагивается
  (так подтверждён Google как ресурс-домен).

Файл подтверждения удалять нельзя: панели перепроверяют права время от времени.

### Цифры внутри админки

Экран «Аналитика» показывает настоящие данные из `content/stats.json`. Файл наполняет
workflow `.github/workflows/stats.yml`: раз в шесть часов он обращается к API Метрики и
коммитит результат. Токен лежит в секрете репозитория `METRIKA_TOKEN` — это и есть та
серверная сторона, которой нет у статического хостинга; в браузер токен не попадает.

Как получить токен: на `oauth.yandex.ru` создать приложение с правом Метрики
«получение статистики», затем открыть
`https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>` и скопировать
выданный токен в Settings → Secrets and variables → Actions → `METRIKA_TOKEN`.
Первый сбор запускается вручную: Actions → «Обновить статистику Метрики» → Run workflow.

Коммиты со статистикой не пересобирают сайт (`paths-ignore` в deploy.yml) и на сайт не
выкладываются. Но репозиторий публичный, поэтому сами цифры посещаемости видны всем,
кто откроет `content/stats.json` в репозитории.

Счётчик встанет на все страницы, а сайт начнёт отправлять события:
`video_play`, `youtube_click`, `telegram_click`, `read_end` (дочитывание), `search`.
Цели с такими же именами нужно создать в кабинете счётчика.
Цифры смотрите там же: чтобы показывать их внутри админки, нужен сервер с токеном
к Reporting API — на статическом хостинге его нет.

## Локальная работа

```bash
node scripts/build.mjs          # сборка в dist/
cd dist && python3 -m http.server 8000
```

Адрес сборки задаётся переменной `SITE_URL` (по умолчанию берётся из `content/site.json`).

## Шрифты

Gilroy (Medium 500, SemiBold 600, Bold 700, ExtraBold 800, Heavy 900 и Italic) взят из
шрифтов, уже лежащих в этом репозитории, урезан до кириллицы с латиницей и переведён в
WOFF2 — 6 файлов примерно по 16 КБ. Лицензия на шрифт — у владельца проекта.

## Ограничения, о которых стоит знать

- Хостинг статический, поэтому **редиректы со старых адресов — HTML-редиректы**
  (`canonical` + мгновенный переход), а не серверный 301. Поисковики их понимают,
  но это не то же самое. Настоящий 301 появится, если однажды переехать на Cloudflare
  Pages / Netlify / свой nginx — контент и сборка при этом не меняются.
- Вход в админку — по персональному токену GitHub, а не по паре логин-пароль:
  права проверяет сам GitHub на своей стороне. Токен хранится в браузере;
  на чужом устройстве снимайте галочку «Запомнить».
- Админка живёт по адресу `/admin/`, а не на поддомене `admin.` — на GitHub Pages
  поддомен с отдельной авторизацией не сделать.
- Редактор блочный (роль блока выбирается кнопкой), а не полноценный WYSIWYG:
  внутри текста работают только `**жирный**` и `[ссылка](адрес)`.
- Демо-статьи помечены плашкой «Демо-материал» — это образцы вёрстки,
  факты в них нужно проверить и переписать перед настоящей публикацией.
